# 成长星球 Growth Planet — 产品需求文档（PRD）

> 版本：v0.1（架构规划阶段）｜日期：2026-10-11｜状态：草案，待评审

## 1. 产品定位

「成长星球」是面向中国小学一年级儿童及其家长的**家庭成长管理系统**。它不是简单的打卡工具，而是把以下五件事放到同一套数据模型里：

1. **家庭任务执行**：任务模板 → 每日任务实例 → 提交 → 审核 → 奖励。
2. **自主能力训练**：记录"家长提醒了几次"，奖励自主开始、主动检查、按时切换活动。
3. **物品位置追踪**：智能书包清单、放学核对、物品位置事件历史、遗失与找回。
4. **积分经济**：成长经验 XP（只增不减）与可消费金币 Coins（可消费、可审核扣分）双资产。
5. **成长分析**：日/周/月趋势报表，只做观察，不做诊断。

## 2. 教育设计原则（产品红线）

这些原则会落到代码约束和测试里，不只是文案：

| 编号 | 原则 | 系统约束 |
|---|---|---|
| P1 | 奖励努力、检查行为和自主完成，而不是只奖励正确答案 | 积分公式包含"自主程度加成""自我检查加成"，不含"正确率加成" |
| P2 | 系统不自动扣分 | 代码中不存在任何自动产生扣分流水的路径；扣分只能由家长发起并二次确认 |
| P3 | 普通遗忘、能力不足、无意识身体习惯不扣分 | 扣分规则需声明适用范围；习惯模块与积分扣分**没有数据通路** |
| P4 | 未确认 ≠ 丢失 | 物品"位置"与"遗失状态"分离建模；只有家长可以标记"疑似遗失" |
| P5 | 不制造打卡焦虑 | 连续类成就使用"弹性窗口"（如 7 天中 5 天），断签不清零已获得的徽章 |
| P6 | 亲子陪伴、基本生活需求、休息不能被商品化 | 商城创建时进行关键词提示和政策确认；文档与家长手册明确说明 |
| P7 | 不做医学诊断 | 报表和习惯模块不输出任何疾病判断性文案；界面固定显示免责说明 |
| P8 | 数据最小化 | 孩子只需昵称、年级、头像；不收集身份证、生日、学校全称、精确定位 |

## 3. 用户角色

| 角色 | 说明 | 主要设备 |
|---|---|---|
| 家庭（Family） | 数据隔离单元，所有业务数据归属一个家庭 | — |
| 家长（Parent） | 配置、审核、管理、导出；可有多位家长（预留） | 手机、电脑 |
| 孩子（Child） | 查看任务、提交完成、查看积分、许愿、申请兑换；可有多个孩子（预留） | iPad、家长手机（孩子模式）、安卓平板 |

## 4. 功能需求

### 4.1 账户与家庭（M-Identity）

- 家长注册创建家庭（首次部署时通过命令行创建首位家长，不内置默认账号密码）。
- 家长使用用户名/邮箱 + 密码登录。
- 孩子登录方式：**家长授权设备 + 孩子选择头像 + 输入 4–6 位 PIN**（PIN 可由家长关闭，仅限已授权设备）。
- 孩子模式退出到家长界面需要家长密码。
- 敏感操作（扣分确认、撤销流水、撤销审核、修改积分上限、导出、删除数据、修改 PIN、备份恢复）需在 10 分钟内重新验证家长密码（可配置）。
- 预留：多家长邀请、多孩子切换。

**验收标准**：孩子账户调用任何 `/api/v1/parent/*` 接口返回 403；跨家庭访问任何资源返回 404。

### 4.2 任务管理引擎（M-Task）

**任务类型**

| 类型代码 | 名称 | 生成方式 |
|---|---|---|
| `daily` | 每日重复任务 | 每天按规则生成（可排除周末/节假日） |
| `weekly` | 每周重复任务 | 每周指定星期几生成 |
| `dated` | 指定日期任务 | 在指定日期列表生成 |
| `adhoc` | 临时任务 | 家长或系统即时创建单个实例 |
| `multi_step` | 多步骤任务 | 是一种"结构"，可与上述重复规则组合 |
| `item_check` | 物品核对任务 | 绑定书包清单或放学核对清单 |
| `habit` | 习惯养成任务 | 绑定自主训练标签（如按时洗漱），统计趋势 |
| `manual` | 家长手动创建任务 | 家长临时下发，不来自模板 |

> 设计说明：类型分为两个维度——**调度方式**（daily/weekly/dated/once）与**任务形态**（普通/多步骤/物品核对/习惯）。文档中的 8 种类型都由这两个维度组合得到，见 `DATABASE.md` §4。

**任务字段**：标题、说明、分类、图标、颜色、计划时间、截止时间、重复规则、有效日期、基础金币、基础经验、审核方式、必选步骤、可选步骤、提醒规则、状态、实际开始/完成时间、提醒次数、完成质量、自主程度、操作人、审核人、备注、附件。

**模板与实例分离**：模板只是"配方"；每天生成的实例保存完整快照（`snapshot` JSON + 关键字段冗余列），模板修改不影响已生成实例。模板修改会让版本号 +1，次日起的新实例使用新版本。

**状态机**：

```
            ┌────────── skip(家长) ─────────┐
            ▼                               │
pending ──start──▶ in_progress ──submit──▶ submitted ──approve──▶ completed
   │                   │                     │    ▲                   │
   │                   │                     │    │ resubmit          │ revoke(家长,二次验证)
   │                   │                  reject  │                   ▼
   │                   │                     ▼    │               submitted（反向流水冲正）
   │                   │                  rejected┘
   └──── 超过截止+宽限期(系统) ──▶ expired ──late_submit(若允许)──▶ submitted
```

状态：待开始 `pending`、进行中 `in_progress`、待审核 `submitted`、已完成 `completed`、已拒绝 `rejected`、已跳过 `skipped`、已过期 `expired`。

**审核方式**：`auto`（提交即完成并发分）、`parent`（家长审核）、`parent_with_photo`（需附照片后家长审核）。

**家长纠错**：撤销审核（生成反向流水）、修改提醒次数/质量后重新审核、撤销跳过、代孩子提交（记录操作人为家长）。

### 4.3 自主能力训练（M-Autonomy，属于任务模块的子域）

**训练标签**（模板可设置 `autonomy_tag`）：

| 标签 | 含义 | 关键数据 |
|---|---|---|
| `start_homework` | 按时开始作业 | 计划开始时间 vs 实际开始时间、提醒次数 |
| `check_homework` | 主动检查作业 | 是否自查、自己发现的错误数、漏题数（仅记录） |
| `end_play` | 按时结束娱乐 | 计划结束时间 vs 实际结束时间、提醒次数 |
| `pack_bag` | 主动整理书包 | 关联书包清单完成情况 |
| `wash_up` | 主动洗漱 | 提醒次数 |
| `tidy_up` | 整理个人物品 | 提醒次数 |
| `reading` | 阅读 | 时长/页数（可选） |

**自主程度**由家长确认，系统根据提醒次数给出建议值：

| 等级 | 名称 | 默认判定（可配置） |
|---|---|---|
| L3 | 完全自主 | 0 次提醒 |
| L2 | 一次提醒 | 1 次 |
| L1 | 多次提醒 | 2–3 次 |
| L0 | 家长协助 | >3 次或家长陪同完成 |

每个等级对应的金币/经验加成由家长在「自主奖励规则」中配置；**L0 不扣分，只是没有加成**。

### 4.4 智能书包管理（M-Item + M-Schedule，核心模块）

详见 `ITEM_TRACKING.md`。要点：

- 物品档案：名称、分类、照片、所有人、默认存放地点、当前已确认位置、最后确认时间与确认人、是否每日检查、是否允许长期留校、是否重要、备注。
- **位置**（家里/书包/学校/其他位置/借出）与**确认状态**（已确认/待确认）与**遗失状态**（正常/疑似遗失/寻找中/已找回/确认遗失）三者分离。
- 物品位置事件历史只追加，不可修改或删除。
- 每周课程表 + 日期例外（放假、调休、临时课表）。
- 根据次日课程表 + 每日必带物品 + 家长临时要求生成书包清单。
- 孩子逐项确认"已放入"；缺失项进入"寻找 → 备注 → 重新确认"流程。
- 放学核对：校牌、水杯、课本、作业本、文具盒及自定义物品；结果为已带回/留校/待确认/疑似遗失/已找回。
- 所有核对结果保留历史。

### 4.5 积分经济（M-Points）

详见 `POINTS_RULES.md`。要点：XP 与 Coins 两个独立账户；复式记账式流水；禁止负余额；事务 + 行锁 + 幂等键；撤销只用反向流水；每日奖励上限、单次扣分上限可配置。

### 4.6 扣分与习惯管理（M-Points + M-Habit）

- 扣分流程：家长选择扣分规则 → 填写原因 → 预览 → 二次验证确认 → 生成流水。
- 每次扣分记录：原因、规则、金额、操作人、确认人、时间。
- 扣分规则需勾选"本规则不针对遗忘、能力不足或无意识习惯"声明后才能启用。
- 习惯模块独立：观察时间、场景、可能诱因、孩子是否意识到、是否使用替代行为、家长备注、阶段目标。
- 习惯模块只能产生**奖励**（如"使用了替代行为""自己意识到了"），不能产生扣分。
- 页面固定显示："本记录用于家庭观察，不构成医学诊断。如有担忧请咨询专业医生。"

### 4.7 愿望商城（M-Shop）

- 家长创建商品：分类、图片、价格、库存、限购（每日/每周/每月/总计）、上下架。
- 孩子提交愿望 → 家长审核 → 可"一键转为商品"。
- 兑换流程：孩子申请（冻结额度校验） → 家长审批（事务扣款） → 履约（待安排/已安排/已履约） → 可取消并退款。
- 商品快照写入订单，下架/改价不影响历史订单。
- 未履约订单在家长首页醒目展示，超过 N 天（可配置）提醒。
- 创建商品时若名称/描述命中"陪伴、睡觉、吃饭、休息、拥抱、讲故事"等关键词，提示违背 P6 原则并要求家长确认。

### 4.8 成长等级与成就（M-Achievement）

- XP 等级（默认 1–300 级，曲线可配置）与成长称号（如"星球学徒""星际探索者"）。
- 徽章：连续自主开始作业、连续主动检查、连续整理书包、自我管理进步、阅读成长等。
- "连续"采用弹性窗口（默认 7 天内达成 5 天），不惩罚断签。
- 徽章一旦获得永不因扣分撤销；仅当家长撤销"误审核"导致条件从未真实满足时，可由家长手动撤销并留审计。

### 4.9 数据统计（M-Report）

- 日/周/月报表：任务完成率、自主完成率、平均提醒次数、作业漏题记录、活动切换表现、物品遗失与找回、金币收入支出、兑换记录、习惯训练趋势。
- 导出 CSV / Excel（xlsx），导出需二次验证并写审计日志。
- 报表页固定免责声明，不出现"疑似多动症"等诊断性措辞。

### 4.10 界面

- **孩子端**：成长星球游戏化风格；大卡片、大按钮（触控目标 ≥ 56px）、简洁中文 + 图标；完成任务有星星/金币动画（尊重系统"减弱动态效果"设置）；愿望进度条。
- **家长端**：Element Plus 管理后台风格；手机端使用独立的卡片式列表布局和底部导航，而不是缩小的桌面表格。
- PWA：可添加到主屏幕；离线时显示缓存的任务列表，提交操作需在线（P8 之后评估离线队列）。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 时区 | 存储 UTC，业务日期按家庭时区（默认 Asia/Shanghai）计算，API 输出带 `+08:00` 偏移的 ISO 8601 |
| 字符集 | MySQL `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 性能 | 单家庭规模，P95 接口 < 300ms；每日任务生成 < 1s |
| 可用性 | 单机部署；每日自动备份；恢复演练脚本 |
| 浏览器 | iOS Safari 16.4+、Android Chrome 最新两个大版本、桌面 Chrome/Edge/Safari |
| 无障碍 | 对比度满足 WCAG AA；动画可关闭 |

## 6. 非目标（当前版本不做）

- 不做多家庭 SaaS 计费、开放注册。
- 不接入第三方 AI、云端照片识别、第三方统计 SDK。
- 不做原生 App（PWA 满足需求）。
- 不做家校通、作业批改、题库。
- Web Push 推送放在后期（需 VAPID 与 iOS 主屏安装），初期以应用内提醒为主。

## 7. 需求歧义与假设

| 编号 | 歧义 | 采用的假设（均可配置） |
|---|---|---|
| A1 | "XP 只增不减"与"家长撤销误审核"冲突 | XP 不因任何扣分减少；家长撤销**误审核**时允许对该笔 XP 做反向冲正（视为数据纠错，单独流水类型 `xp_correction`，需二次验证）。可在设置中关闭 |
| A2 | 兑换何时扣款 | 申请时校验"可用余额 = 余额 − 待审批冻结额"，审批通过时事务扣款 |
| A3 | 孩子如何登录 | 家长授权设备 + PIN，见 §4.1 |
| A4 | 一天的边界 | 默认 00:00（家庭时区），可配置为如 04:00 以覆盖睡前任务 |
| A5 | 过期任务能否补交 | 模板级配置 `allow_late_submit`，默认允许，补交标记 `is_late`，不扣分 |
| A6 | 每日奖励上限是否包含家长手动奖励 | 默认包含任务奖励，不包含家长手动奖励；可配置 |
| A7 | 提醒次数谁来记录 | 家长在自己设备上点"提醒了一次"；孩子端不能修改；审核时家长可最终修正 |
| A8 | 扣分"家长确认"是否需要第二位家长 | 单家长家庭：同一家长"预览 + 密码二次验证"即视为确认；多家长时可配置为需另一位家长确认 |
| A9 | 节假日数据来源 | 不依赖第三方 API；家长手动维护日期例外，提供"导入国务院放假安排 CSV"功能（后期） |
| A10 | MySQL 版本 | MySQL 8.0 已于 2026-04 结束支持，采用 **MySQL 8.4 LTS**（仍属 MySQL 8 系列） |
